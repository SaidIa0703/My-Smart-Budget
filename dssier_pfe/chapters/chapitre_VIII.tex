\chapter{Déploiement et CI/CD}

\section{Containerisation avec Docker}

La stratégie de containerisation de \textbf{My Smart Budget} utilise Docker pour garantir la reproductibilité entre développement et production. L'architecture multi-conteneurs sépare les responsabilités : application Node.js, base MongoDB, et cache Redis.

\subsection{Architecture Docker multi-stage optimisée}

\begin{exemple}
\textbf{Dockerfile multi-stage pour My Smart Budget (Backend) :}
\begin{lstlisting}[language=dockerfile]
# Dockerfile.backend
# Stage 1: Dependencies
FROM node:18-alpine AS dependencies
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production

# Stage 2: Build
FROM node:18-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 3: Production
FROM node:18-alpine AS production

# Créer utilisateur non-root pour sécurité
RUN addgroup -g 1001 -S nodejs && \
    adduser -S nodejs -u 1001

WORKDIR /app

# Copier uniquement les fichiers nécessaires
COPY --chown=nodejs:nodejs --from=dependencies /app/node_modules ./node_modules
COPY --chown=nodejs:nodejs --from=build /app/dist ./dist
COPY --chown=nodejs:nodejs package*.json ./

# Configuration sécurité
USER nodejs
EXPOSE 3001

# Health check
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD node dist/healthcheck.js || exit 1

# Variables d'environnement par défaut
ENV NODE_ENV=production \
    PORT=3001 \
    LOG_LEVEL=info

# Démarrage avec gestion graceful shutdown
CMD ["node", "dist/server.js"]
\end{lstlisting}
\end{exemple}

\begin{exemple}
\textbf{Dockerfile optimisé pour React (Frontend) :}
\begin{lstlisting}[language=dockerfile]
# Dockerfile.frontend
# Stage 1: Build
FROM node:18-alpine AS build
WORKDIR /app

# Cache des dépendances
COPY package*.json ./
RUN npm ci

# Build de l'application
COPY . .
ARG REACT_APP_API_URL
ENV REACT_APP_API_URL=$REACT_APP_API_URL
RUN npm run build

# Stage 2: Serve avec Nginx
FROM nginx:1.24-alpine AS production

# Configuration sécurité Nginx
RUN rm -rf /etc/nginx/conf.d/* && \
    rm -rf /usr/share/nginx/html/*

# Copier build React
COPY --from=build /app/build /usr/share/nginx/html

# Configuration Nginx optimisée
COPY nginx.conf /etc/nginx/conf.d/default.conf

# Utilisateur non-root
RUN chown -R nginx:nginx /usr/share/nginx/html && \
    chmod -R 755 /usr/share/nginx/html

USER nginx
EXPOSE 80

# Health check
HEALTHCHECK --interval=30s --timeout=3s \
  CMD wget --no-verbose --tries=1 --spider http://localhost/ || exit 1

CMD ["nginx", "-g", "daemon off;"]
\end{lstlisting}
\end{exemple}

\subsection{Orchestration avec Docker Compose}

\begin{exemple}
\textbf{docker-compose.yml pour environnement complet :}
\begin{lstlisting}[language=yaml]
version: '3.8'

services:
  # Frontend React
  frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile
      args:
        REACT_APP_API_URL: http://localhost:3001
    image: mysmartbudget/frontend:${VERSION:-latest}
    container_name: msb-frontend
    ports:
      - "3000:80"
    depends_on:
      - backend
    networks:
      - app-network
    restart: unless-stopped
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.frontend.rule=Host(`mysmartbudget.com`)"
    healthcheck:
      test: ["CMD", "wget", "--spider", "-q", "http://localhost/"]
      interval: 30s
      timeout: 3s
      retries: 3

  # Backend Node.js
  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    image: mysmartbudget/backend:${VERSION:-latest}
    container_name: msb-backend
    ports:
      - "3001:3001"
    environment:
      - NODE_ENV=production
      - PORT=3001
      - MONGODB_URI=mongodb://mongodb:27017/mysmartbudget
      - REDIS_URL=redis://redis:6379
      - JWT_SECRET=${JWT_SECRET}
      - JWT_REFRESH_SECRET=${JWT_REFRESH_SECRET}
      - ENCRYPTION_KEY=${ENCRYPTION_KEY}
      - LOG_LEVEL=info
    depends_on:
      mongodb:
        condition: service_healthy
      redis:
        condition: service_healthy
    networks:
      - app-network
    restart: unless-stopped
    volumes:
      - ./logs:/app/logs
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3001/health"]
      interval: 30s
      timeout: 5s
      retries: 3

  # MongoDB
  mongodb:
    image: mongo:6.0.12
    container_name: msb-mongodb
    ports:
      - "27017:27017"
    environment:
      - MONGO_INITDB_ROOT_USERNAME=${MONGO_ROOT_USER:-admin}
      - MONGO_INITDB_ROOT_PASSWORD=${MONGO_ROOT_PASSWORD}
      - MONGO_INITDB_DATABASE=mysmartbudget
    volumes:
      - mongodb_data:/data/db
      - ./mongo-init:/docker-entrypoint-initdb.d
    networks:
      - app-network
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "mongosh", "--eval", "db.adminCommand('ping')"]
      interval: 10s
      timeout: 5s
      retries: 5
    command: ["--auth", "--bind_ip_all"]

  # Redis Cache
  redis:
    image: redis:7.2-alpine
    container_name: msb-redis
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    networks:
      - app-network
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
    command: ["redis-server", "--appendonly", "yes"]

  # MongoDB Backup
  mongo-backup:
    image: tutum/mongodb-backup
    container_name: msb-mongo-backup
    environment:
      - MONGODB_HOST=mongodb
      - MONGODB_PORT=27017
      - MONGODB_USER=${MONGO_ROOT_USER:-admin}
      - MONGODB_PASS=${MONGO_ROOT_PASSWORD}
      - CRON_TIME=0 2 * * *  # Backup quotidien à 2h
      - MAX_BACKUPS=7
    volumes:
      - ./backups:/backup
    networks:
      - app-network
    depends_on:
      - mongodb

networks:
  app-network:
    driver: bridge
    ipam:
      config:
        - subnet: 172.28.0.0/16

volumes:
  mongodb_data:
    driver: local
  redis_data:
    driver: local
\end{lstlisting}
\end{exemple}

\section{Pipeline CI/CD avec GitHub Actions}

\subsection{Architecture du pipeline complet}

Le pipeline CI/CD de My Smart Budget automatise l'ensemble du cycle de développement, du commit au déploiement en production, avec des contrôles qualité à chaque étape.

\begin{exemple}
\textbf{Pipeline CI/CD principal (.github/workflows/main.yml) :}
\begin{lstlisting}[language=yaml]
name: My Smart Budget CI/CD Pipeline

on:
  push:
    branches: [main, develop]
    tags: ['v*']
  pull_request:
    branches: [main]
  schedule:
    - cron: '0 0 * * 0' # Scan sécurité hebdomadaire

env:
  NODE_VERSION: '18'
  MONGODB_VERSION: '6.0'

jobs:
  # Job 1: Analyse de code et linting
  code-quality:
    name: Code Quality Check
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
        with:
          fetch-depth: 0 # Pour SonarQube

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install dependencies
        run: |
          npm ci --prefix backend
          npm ci --prefix frontend

      - name: Run ESLint
        run: |
          npm run lint --prefix backend
          npm run lint --prefix frontend

      - name: TypeScript type check
        run: |
          npm run type-check --prefix backend
          npm run type-check --prefix frontend

      - name: Check for secrets in code
        uses: trufflesecurity/trufflehog@main
        with:
          path: ./
          base: main
          head: HEAD

  # Job 2: Tests unitaires et intégration
  test:
    name: Run Tests
    runs-on: ubuntu-latest
    needs: code-quality
    strategy:
      matrix:
        service: [backend, frontend]
    
    services:
      mongodb:
        image: mongo:${{ env.MONGODB_VERSION }}
        ports:
          - 27017:27017
        options: >-
          --health-cmd "mongosh --eval 'db.adminCommand({ping: 1})'"
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

      redis:
        image: redis:7-alpine
        ports:
          - 6379:6379
        options: >-
          --health-cmd "redis-cli ping"
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci --prefix ${{ matrix.service }}

      - name: Run unit tests
        run: npm run test:unit --prefix ${{ matrix.service }} -- --coverage
        env:
          MONGODB_URI: mongodb://localhost:27017/test
          REDIS_URL: redis://localhost:6379
          JWT_SECRET: test-secret-key
          NODE_ENV: test

      - name: Run integration tests
        if: matrix.service == 'backend'
        run: npm run test:integration --prefix backend
        env:
          MONGODB_URI: mongodb://localhost:27017/test-integration
          REDIS_URL: redis://localhost:6379

      - name: Upload coverage
        uses: codecov/codecov-action@v3
        with:
          token: ${{ secrets.CODECOV_TOKEN }}
          file: ./${{ matrix.service }}/coverage/lcov.info
          name: ${{ matrix.service }}-coverage

  # Job 3: Build et scan de sécurité
  build-and-scan:
    name: Build & Security Scan
    runs-on: ubuntu-latest
    needs: test
    outputs:
      version: ${{ steps.version.outputs.version }}
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Generate version
        id: version
        run: |
          if [[ "${{ github.ref }}" == refs/tags/v* ]]; then
            VERSION=${GITHUB_REF#refs/tags/}
          else
            VERSION=$(date +%Y%m%d)-${GITHUB_SHA::8}
          fi
          echo "version=${VERSION}" >> $GITHUB_OUTPUT

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to GitHub Container Registry
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build Backend Docker image
        uses: docker/build-push-action@v5
        with:
          context: ./backend
          push: false
          tags: |
            ghcr.io/mysmartbudget/backend:${{ steps.version.outputs.version }}
            ghcr.io/mysmartbudget/backend:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max
          outputs: type=docker,dest=/tmp/backend.tar

      - name: Build Frontend Docker image
        uses: docker/build-push-action@v5
        with:
          context: ./frontend
          push: false
          tags: |
            ghcr.io/mysmartbudget/frontend:${{ steps.version.outputs.version }}
            ghcr.io/mysmartbudget/frontend:latest
          build-args: |
            REACT_APP_API_URL=${{ secrets.PROD_API_URL }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
          outputs: type=docker,dest=/tmp/frontend.tar

      - name: Run Trivy security scan
        uses: aquasecurity/trivy-action@master
        with:
          input: /tmp/backend.tar
          format: 'sarif'
          output: 'trivy-backend.sarif'
          severity: 'CRITICAL,HIGH'

      - name: Upload Trivy scan results
        uses: github/codeql-action/upload-sarif@v2
        with:
          sarif_file: 'trivy-backend.sarif'

      - name: Run Snyk security scan
        uses: snyk/actions/node@master
        env:
          SNYK_TOKEN: ${{ secrets.SNYK_TOKEN }}
        with:
          args: --severity-threshold=high

      - name: Push images if main branch
        if: github.ref == 'refs/heads/main' || startsWith(github.ref, 'refs/tags/')
        run: |
          docker load < /tmp/backend.tar
          docker load < /tmp/frontend.tar
          docker push ghcr.io/mysmartbudget/backend:${{ steps.version.outputs.version }}
          docker push ghcr.io/mysmartbudget/frontend:${{ steps.version.outputs.version }}
          if [[ "${{ github.ref }}" == "refs/heads/main" ]]; then
            docker push ghcr.io/mysmartbudget/backend:latest
            docker push ghcr.io/mysmartbudget/frontend:latest
          fi

  # Job 4: Tests E2E
  e2e-tests:
    name: E2E Tests
    runs-on: ubuntu-latest
    needs: build-and-scan
    if: github.event_name == 'pull_request' || github.ref == 'refs/heads/main'
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Start services with Docker Compose
        run: |
          docker-compose -f docker-compose.test.yml up -d
          sleep 30 # Attendre le démarrage

      - name: Run Cypress E2E tests
        uses: cypress-io/github-action@v5
        with:
          working-directory: ./e2e
          wait-on: 'http://localhost:3000, http://localhost:3001/health'
          wait-on-timeout: 120
          browser: chrome
          record: true
        env:
          CYPRESS_RECORD_KEY: ${{ secrets.CYPRESS_RECORD_KEY }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      - name: Upload Cypress artifacts
        if: failure()
        uses: actions/upload-artifact@v3
        with:
          name: cypress-artifacts
          path: |
            e2e/cypress/videos
            e2e/cypress/screenshots

  # Job 5: Performance tests
  performance-tests:
    name: Performance Tests
    runs-on: ubuntu-latest
    needs: build-and-scan
    if: github.ref == 'refs/heads/main'
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Start application
        run: |
          docker-compose up -d
          sleep 30

      - name: Run k6 load tests
        uses: grafana/k6-action@v0.3.0
        with:
          filename: tests/k6/scenarios/load-test.js
          flags: |
            --out json=results.json
            --summary-export=summary.json

      - name: Upload k6 results
        uses: actions/upload-artifact@v3
        with:
          name: k6-results
          path: |
            results.json
            summary.json

      - name: Check performance thresholds
        run: |
          node scripts/check-k6-thresholds.js summary.json

  # Job 6: Déploiement Staging
  deploy-staging:
    name: Deploy to Staging
    runs-on: ubuntu-latest
    needs: [build-and-scan, e2e-tests]
    if: github.ref == 'refs/heads/develop'
    environment: staging
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Deploy Backend to Render (Staging)
        run: |
          curl -X POST https://api.render.com/v1/services/${{ secrets.RENDER_STAGING_SERVICE_ID }}/deploys \
            -H "Authorization: Bearer ${{ secrets.RENDER_API_KEY }}" \
            -H "Content-Type: application/json" \
            -d '{"clearCache": true}'

      - name: Deploy Frontend to Vercel (Staging)
        uses: amondnet/vercel-action@v25
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}
          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}
          working-directory: ./frontend
          alias-domains: staging.mysmartbudget.com

      - name: Run smoke tests
        run: |
          npm run test:smoke -- --env=staging
        env:
          STAGING_URL: https://staging.mysmartbudget.com

      - name: Notify Slack
        uses: 8398a7/action-slack@v3
        with:
          status: ${{ job.status }}
          text: 'Staging deployment completed for version ${{ needs.build-and-scan.outputs.version }}'
          webhook_url: ${{ secrets.SLACK_WEBHOOK }}

  # Job 7: Déploiement Production
  deploy-production:
    name: Deploy to Production
    runs-on: ubuntu-latest
    needs: [build-and-scan, e2e-tests, performance-tests]
    if: github.ref == 'refs/heads/main' || startsWith(github.ref, 'refs/tags/')
    environment: production
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Create GitHub Release
        if: startsWith(github.ref, 'refs/tags/')
        uses: softprops/action-gh-release@v1
        with:
          generate_release_notes: true
          files: |
            CHANGELOG.md
            docs/RELEASE_NOTES.md

      - name: Deploy Backend to Render (Production)
        run: |
          curl -X POST https://api.render.com/v1/services/${{ secrets.RENDER_PROD_SERVICE_ID }}/deploys \
            -H "Authorization: Bearer ${{ secrets.RENDER_API_KEY }}" \
            -H "Content-Type: application/json" \
            -d '{"clearCache": false}'

      - name: Deploy Frontend to Vercel (Production)
        uses: amondnet/vercel-action@v25
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}
          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID_PROD }}
          working-directory: ./frontend
          prod: true

      - name: Run smoke tests
        run: |
          npm run test:smoke -- --env=production
        env:
          PROD_URL: https://mysmartbudget.com

      - name: Update deployment status
        run: |
          curl -X POST ${{ secrets.STATUS_PAGE_URL }}/api/deployments \
            -H "Authorization: Bearer ${{ secrets.STATUS_PAGE_TOKEN }}" \
            -d '{
              "version": "${{ needs.build-and-scan.outputs.version }}",
              "environment": "production",
              "status": "success",
              "timestamp": "'$(date -u +"%Y-%m-%dT%H:%M:%SZ")'"
            }'

      - name: Notify team
        uses: 8398a7/action-slack@v3
        with:
          status: ${{ job.status }}
          text: |
            🚀 Production deployment completed!
            Version: ${{ needs.build-and-scan.outputs.version }}
            Environment: Production
            URL: https://mysmartbudget.com
          webhook_url: ${{ secrets.SLACK_WEBHOOK }}
\end{lstlisting}
\end{exemple}

# My Smart Budget - Runbook Opérationnel

## 1. Architecture Overview
- **Frontend:** React sur Vercel (CDN global)
- **Backend:** Node.js sur Render (US-East)
- **Database:** MongoDB Atlas (Replica Set M10)
- **Cache:** Redis sur Render
- **Monitoring:** Grafana Cloud + UptimeKuma

## 2. Procédures de démarrage

### Démarrage local (développement)
```bash
# Cloner le repository
git clone https://github.com/mysmartbudget/app.git

# Installer les dépendances

npm install --prefix frontend

# Copier les variables d'environnement
cp backend/.env.example backend/.env

docker-compose ps
curl http://localhost:3001/health
```

### Vérifications de santé
```bash
# Backend health check
curl https://api.mysmartbudget.com/health

# MongoDB status
mongosh $MONGODB_URI --eval "db.adminCommand('ping')"

# Redis ping
redis-cli -h redis.mysmartbudget.com ping
```

## 3. Procédures d'urgence

### Incident: API Down
1. Vérifier le status sur https://status.mysmartbudget.com
2. Consulter les logs: `render logs --service api --tail 100`
3. Redémarrer le service: `render restart --service api`
4. Si persistant, rollback: `render deploy --service api --commit LAST_KNOWN_GOOD`

### Incident: Database Connection Issues
1. Vérifier MongoDB Atlas: https://cloud.mongodb.com
2. Check connection string: `echo $MONGODB_URI`
3. Test connection: `mongosh $MONGODB_URI`
4. Si connection pool épuisé:
   ```javascript
   // Augmenter temporairement le pool
   mongoose.connect(uri, { 
     maxPoolSize: 20, // Augmenter de 10 à 20
     serverSelectionTimeoutMS: 5000
   });
   ```

### Incident: Haute latence
1. Identifier l'endpoint lent dans Grafana
2. Vérifier les index MongoDB:
   ```javascript
   db.transactions.getIndexes()
   // Si index manquant:
   db.transactions.createIndex({ userId: 1, date: -1 })
   ```
3. Vider le cache Redis: `redis-cli FLUSHDB`
4. Scale horizontalement si nécessaire

## 4. Procédures de maintenance

### Backup MongoDB (automatique + manuel)
```bash
# Backup manuel d'urgence
mongodump --uri="$MONGODB_URI" --out=backup_$(date +%Y%m%d_%H%M%S)

# Restauration
mongorestore --uri="$MONGODB_URI" --dir=backup_20240115_143022
```

### Rotation des logs
```bash
# Logs applicatifs (Winston)
find /app/logs -name "*.log" -mtime +30 -delete

# Archivage
tar -czf logs_archive_$(date +%Y%m).tar.gz /app/logs/*.log
aws s3 cp logs_archive_*.tar.gz s3://mysmartbudget-archives/logs/
```

### Mise à jour des dépendances
```bash
# Scan des vulnérabilités
npm audit --prefix backend
npm audit --prefix frontend

# Mise à jour sécurisée
npm update --save --prefix backend
npm update --save --prefix frontend

# Test après mise à jour
npm test --prefix backend
npm test --prefix frontend
```
